
## Scope note — you are building software, not running a process

The specification above was written for a team working under a formal
engineering protocol, so it names artifacts and ceremonies from that protocol
(work packages, fan-out, review ladders, contract documents). **None of that
applies to you.** You are one agent building one program.

Read the spec for exactly two things: the behavior the server must have, and
the goals and non-goals that tell you what is in scope. Ignore every sentence
about process, artifacts, or how a team would organize itself — producing
those documents is not part of your task and will not be graded.

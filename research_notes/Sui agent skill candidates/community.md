# Community Sui/Move/Walrus agent-skill candidates

## Which community candidates are credible enough to assess?

### Takeaway

The strongest community candidates are narrow: `exvulsec/sui-move-skill` for source-backed contract audit workflows and `1NickPappas/move-code-quality-skill` for a lightweight Move quality checklist. `first-mover-tw/sui-dev-agents` is broad and current by its own version claims, but substantially overlaps the Mysten-maintained skills and its README contains an overbroad JSON-RPC shutdown claim. NAVI skills are protocol-specific. Community directories are discovery aids rather than a distinct candidate.

### Cited Findings

Verification was read-only: reviewed public GitHub repository README/SKILL/license pages and raw SKILL.md, queried GitHub’s public REST repository/commit/tree metadata for license, last commit timestamps and file byte counts, and checked the cited official documentation page for the JSON-RPC claim. No candidate was installed, executed, connected to RPC, or given wallet/key access. Approximate tokens use bytes/4. Last commit dates below are GitHub API commit timestamps checked 2026-10-18 (UTC), not claims of semantic correctness.

### Inferences

- A narrower skill’s relevant body is likely cheaper than an always-on Sui rules file, but exact token injection depends on harness trigger/loading behavior and which references are opened; the byte/4 figures are upper-bound text estimates, not observed prompt tokens.
- Community GitHub discovery did not produce a clearly independent comprehensive Sui skill suite that improves on the official Mysten candidate. The useful differentiators are audit process (exvulsec), Move Book quality checklist (1NickPappas), and NAVI protocol operations (only for a NAVI-using project).
- MCP should be evaluated as a distinct authority layer. The community MCPs range from read/query with optional pre-signed transaction forwarding to imported private keys and direct transaction tools; none is required simply to reduce docs fetches.

### Gaps

- No task benchmark or implementation run was performed. This assignment did not authorize installations, network calls to Sui, wallets, test transactions, or scratch worktrees; therefore candidate effect on fleet turns/tokens and correctness remains unmeasured.
- GitHub repo timestamps and file-tree byte totals are reproducible metadata, but do not prove the latest edits were reviewed/tested or that documentation matches current network behavior. In particular, SUI Dev Agents’ README has the JSON-RPC discrepancy noted above.
- No public Sui-specific Codex plugin marketplace entry, independent Cursor-only rules pack, or community list entry beyond those cited was verified. Absence is limited to these public source/list checks, not proof none exists.
- `docsdump` local inventory (inspected read-only): `/home/tedks/Projects/mysten/docsdump` contains only symlinks `move-book -> ../move-book`, `sui-docs -> ../sui/docs`, and `ts-sdk-docs -> ../sui/sdk/docs/`; no `llms.txt` or generated LLM bundle was present there. The `awesome-move` checkout’s last commit is 2023-04-30 and the local Sui checkout’s last commit is 2025-10-02, so this local reference cache should not be treated as current. The directory was checked for files, skills, and llms manifests; none were found in the inspected paths.

## Would writing a small fleet skill from current docs be a credible candidate?

### Takeaway

Yes, as a controlled internal candidate: generate a small routing/index skill that points to current, version-aware primary docs and invokes the locally pinned CLI for validation, rather than bundling a large static documentation dump. This avoids adopting unrelated wallet powers and can be evaluated against the usage-derived pain points by the lead. Keep copied prose and generated content separate until source licensing is checked.

### Cited Findings

- The Sui developer docs expose an LLM index at `https://docs.sui.io/llms.txt`, support page markdown via `.md`, publish Sui Agent Skills, and advertise a docs MCP at `https://sui.mcp.kapa.ai`. The MCP supports source search and exact-URL retrieval; docs say it uses OAuth and per-user daily limits. [Sui developer docs landing](https://www.docs.sui.io/explore); [MCP setup and behavior](https://docs.sui.io/getting-started/sui-mcp-server).
- The docs landing identifies related primary doc sets for Sui, Walrus (`docs.wal.app`), SDK (`sdk.mystenlabs.com`) and Move Book (`move-book.com`), which provides a natural source map for a locally authored router. [Sui developer docs landing](https://www.docs.sui.io/explore).
- Direct HTTP GET checks on 2026-10-18 returned 200 for `llms.txt` on docs.sui.io (43,290 B), sdk.mystenlabs.com (16,798 B), docs.wal.app (78,809 B), and move-book.com (10,886 B); Sui, Walrus, and Move Book also returned `llms-full.txt` (81,744 B; 78,709 B; 983,071 B). SDK `llms-full.txt` returned 404. Rough full-file costs at bytes/4 are respectively 10.8k / 4.2k / 19.7k / 2.7k tokens for indexes and 20.4k / 19.7k / 245.8k tokens for the available full files. These are fetched bytes and rough token estimates, not actual tokenizer counts. [Sui index](https://docs.sui.io/llms.txt); [SDK index](https://sdk.mystenlabs.com/llms.txt); [Walrus index](https://docs.wal.app/llms.txt); [Move Book index](https://move-book.com/llms.txt); [Sui full index](https://docs.sui.io/llms-full.txt); [Walrus full index](https://docs.wal.app/llms-full.txt); [Move Book full index](https://move-book.com/llms-full.txt).
- Official Sui documentation describes supported data access and explicitly says its public-good fullnode URLs are for testing; code should use documented/current gRPC or GraphQL patterns and avoid stale JSON-RPC examples where relevant. [Data stack guidance](https://www.docs.sui.io/operators/data-management/indexer-stack-setup); [gRPC guide](https://www.docs.sui.io/develop/accessing-data/grpc).

### Inferences

- A compact authored skill can target specific repeated errors (CLI/SDK drift, build/test retry loops, data API migration) while keeping references on demand. Design should pin no API version blindly: read the project’s Move.toml/package manifests and use the checked-out toolchain and current official docs as sources of truth.
- An internal-written skill is the clearest route if public candidate assessment finds version drift or unsafe assumptions, but measured pain points and the official candidate’s breadth should determine whether a new artifact is additive.
- Factual summaries with links are safer than copying whole docs pages into a public AGPL repository. The license/redistribution status for each docs source was not established here; no text was copied into this note beyond short names and descriptions.

### Gaps

- The requested LLM manifests were directly fetched and sizes measured; this did not establish content licensing or a stable update cadence. Check the relevant source terms and freshness before copying text into an artifact. Sui SDK `llms-full.txt` was absent (HTTP 404) at check time; do not assume every site provides one.
- No byte/token budget for a future skill can be defended until it is authored; reasonable target is an index plus task-specific references loaded on demand, measured using actual file sizes and harness injection behavior.
- Integration recommendation and source-license ruling remain with Ted. This note does not authorize or perform integration.
